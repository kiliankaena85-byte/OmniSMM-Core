## 🏛 Bounded Contexts (Бизнес-домены)

### 1. 💰 Финансовое Ядро (Ledger & Billing)
* **Зона ответственности:** Балансы пользователей, списания копеек, идемпотентность, транзакции, 54-ФЗ (чеки).
* **Расположение:** `src/lib/financial/`, `src/actions/finance/`
* **Ключевой агрегат:** `WalletOps`
* **Инварианты (Opus Rules):** 
  - [INV-FIN-01] Использовать строго `BigInt` (копейки). Никаких `Number` или float.
  - [INV-FIN-02] Запрет на Transaction Escape (использовать `tx`, а не `db` внутри транзакций).

### 2. 🏬 Витрина и Мульти-тенантность (Storefront)
* **Зона ответственности:** Отображение услуг для пользователей, изоляция брендов (SMMplan vs SMMflux), публичные цены, авторизация запросов к витрине.
* **Расположение:** `src/lib/storefront/`, `src/app/api/storefront/`
* **Инварианты (Opus Rules):**
  - [INV-TENANT-01] Zero Vendor Leaks (Поставщик никогда не должен уйти на клиент).
  - [INV-TENANT-02] Привязка контекста бренда через `x-tenant-id` (или Fallback на `smmplan` для localhost).

### 3. 🔌 Шлюзы Поставщиков (Provider Engines & Shadow Buffer)
* **Зона ответственности:** Синхронизация цен и услуг с ResellerSMM, Vexboost и др.
* **Расположение:** `src/lib/providers/`
* **Ключевой агрегат:** Теневой буфер (Shadow Catalog Buffer).
* **Инварианты (Opus Rules):**
  - [INV-PROV-01] Сырые данные провайдеров пишутся ТОЛЬКО в `ShadowService`.
  - [INV-PROV-02] Запрет на прямое обновление `Service` (каталог витрины) без Cherry-Pick аппрува админом.

### 4. 🛡 Безопасность и Доступ (Auth & RBAC)
* **Зона ответственности:** Авторизация, Middleware-роутинг, VaultService (шифрование API-ключей провайдеров).
* **Расположение:** `src/proxy.ts` (Edge-роутер), `src/lib/security/`
* **Инварианты (Opus Rules):**
  - [INV-SEC-01] Fail-Closed логика валидации Webhooks (отклонять при любом сомнении).
  - [INV-SEC-02] Ключи шифруются через AES-256-GCM.

### 5. 🖥 Server Actions & UI (Фронтенд-мутации)
* **Зона ответственности:** Клиентские компоненты HeroUI v3, Tailwind 4, мутации данных.
* **Расположение:** `src/components/`, `src/actions/`
* **Инварианты (Opus Rules):**
  - [INV-UI-01] Отказ от сдвигов верстки (Zero Hydration Mismatch).
  - [INV-UI-02] Все Server Actions обязаны возвращать строго типизированный ответ `{ success, error }`.
